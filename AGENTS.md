# candybar

Candybar is the **single clock** for recurring work on this host: an
event-driven cron framework for the 33GOD pipeline. One heartbeat publishes
minute ticks onto Bloodbank (`bloodbank.cron.tick.fired`); everything else is a
consumer of bus facts and commands. Candybar owns **when** a job runs; the job
itself can be a systemd `.service`, an external-pinned Hermes job, an n8n
webhook workflow or any exec argv. [`README.md`](README.md) is the operator
manual; read it before changing anything.

## The rule

If you need something to run on a schedule, register a candybar. Never create:

- a crontab entry, a new systemd `.timer`, `systemd-run --on-*`, `at`/`batch`,
  or a launchd interval;
- a Hermes recurring job (the `cronjob` tool, or `hermes cron create` without
  `--scheduler external`);
- an n8n Schedule Trigger;
- a private recurring sleep/poll loop.

Sub-minute cadence is not schedulable here. Use an event-driven worker, loop
inside one invocation, or ask the user for an exact exception record.
Session-scoped waits (Claude Code `CronCreate`, `/loop`, `ScheduleWakeup`) are
in-session waits, not durable schedules; never use them to install recurring
system work.

The only standing exception is AD-22 `candybar-watchdog.timer`
(`deploy/watchdog/README.md`): a scheduler cannot watch its own clock. Any
other exception is an exact, owner-approved entry in
`deploy/scheduling-policy.json`; never grant one to yourself. Global wording:
`~/.agents/AGENTS.md`, "Recurring schedules: Candybar is the single clock".

## Roles

One Python asyncio deployable (`src/candybar/`), roles chosen by
`candybar daemon --roles ...`: `heartbeat` (ticks), `dispatcher` (schedule
evaluation), `executor` (runs the job), `api` (registry writes and reads). The
Postgres registry is the sole inventory and the daemon its only writer. The
container runs heartbeat, dispatcher and api; the executor runs on the host as
`candybar-executor.service` (a `systemd --user` unit) so jobs can reach
`systemctl --user`, `op`, docker and the hermes CLI.

## Registering a job

1. Pick the runner kind: `exec` (script or command), `systemd` (keep the
   `.service`, retire the `.timer`), `hermes` (job pinned external), `n8n`
   (webhook workflow with no Schedule Trigger). Recipes: README, "Runner kinds".
2. Commit `candybar.toml` next to the job's source. Migrated jobs use
   `deploy/migration/manifests/<name>/`; canaries live in `deploy/smoke/`; the
   policy-drift job is `deploy/policy/candybar.toml`.
3. `uv run candybar register <dir>` (create-only; use `edit` or `PATCH` to
   change). Register disabled first if the job has side effects.
4. Read it back (`show`, `next`), prove a terminal invocation and its intended
   effect (`run --wait`, or wait for the first scheduled fire for side-effect
   jobs; `history`), then `resume`.
5. Verify no competing native clock is left, then commit and push.

Moving an existing cron job or timer is a ledger flow, not a hand edit:
`deploy/migration/ledger.yaml` plus `uv run candybar migrate plan|cutover|verify|rollback|decommission`.
See `deploy/migration/README.md`. One scheduler per job at every step.

## Doctor and the ledger

```bash
cd ~/code/33GOD/candybar
uv run candybar doctor --repo . --live --json   # read-only policy lint
uv run candybar migrate status --json           # ledger state
```

Exit 0 is pass, 1 is bypass clocks found, 2 is "could not audit" (never green).
Findings must stay visible; do not auto-disable or migrate unfamiliar timers.
Run doctor from the checkout (`uv run`), not the separately installed uv-tool
copy, because it reads this repo's ledger and policy.

## Policy code: handle with care

`src/candybar/scheduling_policy.py`, `scheduling_drift.py`,
`transition_exec.py`, `src/candybar/cli/doctor.py` and
`deploy/scheduling-policy.json` define and enforce the single-clock rule.
Weakening them (a wildcard exemption, a broader owner map, a silenced finding)
changes what the whole host is allowed to schedule, so do it only on an
explicit instruction. Other agents may have uncommitted edits there: commit only
your own paths.
