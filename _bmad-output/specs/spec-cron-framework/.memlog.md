- (decision) Distill BRAINDUMP.md (wax frontmatter ignored; content starts at '# Cron Overhaul') into the Candybar cron framework spec; headless express mode, no elicitation.
- (capability) CAP-1 heartbeat publisher: a minute-resolution heartbeat event fires onto Bloodbank so subscribers can react; replaces scattered crontab timers.
- (capability) CAP-2 Candybar unit contract: every scheduled unit is a Candybar implementing invoke, schedule (standard cron format), and result (success/fail).
- (capability) CAP-3 per-invoke Prometheus metrics: memory, runtime ms, token spend, avg CPU/GPU load recorded per Candybar invocation.
- (capability) CAP-4 Postgres registry: full inventory with name/description/tags plus invocation metadata (total invoked, total successful).
- (capability) CAP-5 SDKs for node, python, rust so a Candybar can be authored natively in each language.
- (capability) CAP-6 any executable registrable as a Candybar without an SDK (shell scripts, binaries).
- (capability) CAP-7 CLI manual invocation: candybar run {registryId} fires a Candybar immediately.
- (capability) CAP-8 read-side + control API exposing definitions, schedule windows (past/upcoming with countdown data), skip operations, and noise collection for downstream consumers.
- (constraint) Bloodbank is the only scheduling transport: heartbeat and invocation lifecycle publish as bloodbank.evt.* facts over NATS/Dapr; business logic lives in cron Subscribers, never a central crontab.
- (constraint) Schedules use the standard cron format verbatim; no bespoke schedule DSL.
- (constraint) Existing infra only: Prometheus+Grafana for metrics, Postgres for the registry, Candystore as the durable projection of invocation events; no new stores.
- (constraint) Secrets only as op://DeLoSecrets/... references or env vars, never plaintext in repo or config.
- (constraint) Service hostnames on delo.sh in all configuration; never hardcode LAN IPs.
- (constraint) Director Rule: this repo owns the cron framework only (daemon, registry, SDKs, CLI, read-side API); the Holocene view is DELEGATED to the holocene repo — candybar specifies only the API contract it must expose.
- (direction) Delegated epic (owner: holocene): gmail-inbox-style live view with Definitions and Schedule tabs, current/upcoming/past rows, countdowns, noise toggle for <10m crons, skip-a-cron and skip-rest-of-day; candybar supplies the contract, holocene implements the UI.
- (assumption) Daemon and CLI written in Python (.project.json declares primary_language python); SDK languages are independent of daemon language.
- (assumption) Heartbeat granularity is one minute; sub-minute schedules are out of scope (matching the braindump's 'every minute' heartbeat).
- (assumption) Token spend metric applies only to LLM-invoking Candybars; others report zero.
- (assumption) Skip operations (skip-a-cron, skip-rest-of-day) are schedule overrides stored in the registry and honored by the dispatch path; noise collection is a registry-level tag set.
- (question) What is the missed-heartbeat / catch-up policy when the daemon is down (skip, misfire-run-once, or replay all)?
- (question) Is heartbeat delivery at-least-once (subscribers must dedupe within a minute tick) or effectively-once via the daemon?
