## Implementation sequence and collision control

1. **Resolve gates first.** Owner answers land in `t_7204a764`; bmad-spec appends exact decisions and rederives SPEC/companion. Bloodbank `t_ff84ad7e` approves event name, schemas and finite-capable revision, preserving cron v1. Coordinate the shared WIP driver lock for short board transitions; release before waiting. Do not take the concurrent steward/archive lane's uncommitted work.
2. **Design the migration on isolated branch.** `src/candybar/registry/models.py`, `store.py` and Alembic revisions share steward/profile/task FKs; allocate revision after steward lane confirms its head. Add `candybar_records` durable identity, occurrence and deletion outbox tables; repoint history-bearing FKs away from active-row CASCADE (including `invocations`, skips, steward task history). Keep identity of every UUID/name snapshot and existing retention. Distinguish queued work from terminal before 409/cleanup. No destructive migration of existing invocation rows.
3. **Unify schedule strategy.** `src/candybar/dispatcher/{schedule.py,firetimes.py,worker.py}`, executor `worker.py`, API `schedule.py`, registry manifest/schema and API `app.py` use one enumeration interface. Separate cron Vixie/coalescing from owner-approved finite missed policy. Audit Python/Node/Rust SDKs and `candybar.toml`; add variants/validation and PATCH invariants; prove UTC/window/SSE/CLI consistency.
4. **Make settlement the source of truth.** Durable occurrence records with exactly-one claim and terminal disposition, including operator/system skips. Per-candybar lock holds through claim/edit/delete/settlement; late queued commands fence against deleted UUID. Crash/redelivery/out-of-order tests precede self-delete. `src/candybar/api/app.py` history guard and `src/candybar/cli/control.py` active-name resolution must allow UUID history after deletion; do not create a second browser API.
5. **Implement one transactional delete.** Registry removes active row, retains record/tombstone and writes stable-ID outbox entry in one commit. Manual API/CLI and finite auto-cleanup call it; publish/retry on existing daemon event paths. Bloodbank-approved fact only after commit. Check `src/candybar/api/stream.py` event-first overlay and Holocene consumer expectations so deleted rows do not reappear; retain archive semantics.
6. **Verify, review, release.** Local unit/integration gates and docs first; fresh spec-compliance reviewer then fresh quality reviewer; independent release worker pushes reviewed main, deploys and produces real effects/doctor/history proof. Gruvato retirement and final CAND acceptance follow separately. No early live registrations or premature Nov4 deletion.

### Hotspots and known code seams (read-only, planning baseline)

- `src/candybar/registry/models.py` at current planning baseline has `Invocation.candybar_id` ON DELETE CASCADE, `Skip` and `StewardTask`/profile active-row cascades; the concurrent steward lane modifies these paths. `src/candybar/registry/store.py` owns active inventory and history queries.

- `schemas/cron/`, event vocabulary, API/CLI, `alembic/versions/` and SDK parsers are shared surfaces. Preserve owner-approved steward/archive contract at baseline; avoid parallel mutations or unreviewed main merge.
