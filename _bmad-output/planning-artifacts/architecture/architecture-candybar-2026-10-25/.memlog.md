- (decision) AD-1 Paradigm: event-driven heartbeat-and-dispatch. One clock source (heartbeat publisher) emits minute ticks as facts; every downstream behavior (schedule evaluation, dispatch, execution, accounting, UI updates) is a consumer of bus facts/commands. Facts choreographed; dispatch orchestrated by a single dispatcher. Prevents: independent timer loops re-creating the scattered-cron state the product exists to kill.
- (decision) AD-2 One Python deployable, role-composed: heartbeat, dispatcher, executor, and API are roles in a single asyncio process (one systemd-managed container), separable later by CLI role flag. Prevents: four microservices of operational surface for a single-node homelab, and divergent registry access patterns across services.
- (decision) AD-3 Event vocabulary: new Bloodbank domain 'cron' with entities 'tick' and 'candybar', plus action addition 'fired'. Types: bloodbank.cron.tick.fired; bloodbank.cron.candybar.{created,updated,invoked,completed,failed,skipped}; command bloodbank.cron.candybar.invoke (subject bloodbank.cmd.cron.candybar.invoke). MUST be registered in bloodbank/docs/event-naming.md allowlists (PR-first rule) before first emission. Weighed reusing system.heartbeat — rejected: that entity is platform-health liveness, not a scheduling tick, and domain pairing rules forbid it outside system.
- (decision) AD-4 Heartbeat publisher: aligns to wall-clock minute boundary, publishes bloodbank.evt.cron.tick.fired with deterministic tick_id = tick:<unix_epoch_minute> as envelope ordering_key and data.tick_id. Deterministic id makes every downstream dedupe trivial and replay-safe. Skew tolerance: publish within the minute; consumers key on tick_id, not receipt time.
- (decision) AD-5 (resolves spec OQ: delivery semantics) Effectively-once dispatch, at-least-once tick. Only the dispatcher's single durable consumer on bloodbank.evt.cron.tick.> performs schedule evaluation; invoke commands carry idempotency_key candybar:<id>:tick:<tick_id> (scheduled) so redelivered ticks/duplicate commands cannot double-fire. Any other subscriber tapping raw ticks MUST treat delivery as at-least-once and dedupe on tick_id.
- (decision) AD-6 (resolves spec OQ: catch-up policy) Anacron-style coalesce-to-latest. On dispatcher startup, per candybar compute fires missed since last-seen tick; execute only the LATEST missed fire (trigger=misfire), record all earlier missed fires as bloodbank.cron.candybar.skipped with data.reason=misfire_coalesced. Catch-up window capped at 24h; downtime beyond that yields only the latest missed fire. Prevents: thundering-herd replay of hours of missed crons against shared homelab resources.
- (decision) AD-7 Executor-owns-execution: every invocation — SDK-authored or bare executable — runs as a subprocess spawned by the executor under its own cgroup v2 scope. SDK candybars are executables built on the SDK harness; there are no long-running per-candybar bus subscribers in v1. Prevents: two execution models (spawned vs subscriber) with divergent metrics, accounting, and failure semantics.
- (decision) AD-8 SDK contract = process protocol, identical across python/node/rust. In via env: CANDYBAR_INVOCATION_ID, CANDYBAR_ID, CANDYBAR_TRIGGER (scheduled|manual|misfire), CANDYBAR_TICK_ID, CANDYBAR_RESULT_FILE. Out: result JSON at CANDYBAR_RESULT_FILE {status: success|fail, message?, metrics: {token_spend?}}. Exit code is the fallback contract for bare executables (CAP-6): 0=success, nonzero=fail, all metrics except runtime/mem/cpu zeroed. SDK value-add: registration manifest (candybar.toml), invoke() harness with context object, exception-to-fail mapping, token-spend reporting, result-file writing. SDKs never talk to NATS — the bus belongs to the daemon.
- (decision) AD-9 Metrics attribution: Prometheus series are labeled per candybar (+result), NEVER per invocation-id — per-invoke identity rides as histogram/counter EXEMPLARS (invocation_id) and the full per-invoke record lives in the completion event data + invocations table. Prevents: unbounded label cardinality from a per-invocation label. Attribution: executor measures runtime_ms (wall clock), mem_bytes (cgroup memory.peak), cpu_avg (cgroup cpu.stat usec delta / runtime), gpu_avg (nvidia-smi pmon per-pid sampling when a GPU is present, else 0); token_spend is self-reported by the SDK in the result file (LLM candybars), default 0.
- (decision) AD-10 Registry: single Postgres database 'candybar' on the shared homelab Postgres (delo.sh hostname), owned solely by the daemon; alembic migrations. Prevents: counter drift from dual-write paths and a second writer class to the registry.
